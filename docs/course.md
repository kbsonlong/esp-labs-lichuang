# esp-labs-lichuang 课程文本：立创·实战派 ESP32-S3 动手入门

一份给零基础的、插上 USB 就能跑的实战课程。目标板是**立创·实战派 ESP32-S3**：一块把屏幕、麦克风、扬声器、摄像头都焊好的"一体化"板子——所以这门课**全程零接线**，你只需要一根 USB 数据线。

我们一起来：文档带你读懂每一段代码，你负责烧录、观察现象、把看到的报回来。

## 这门课怎么用

每课一个独立工程，放在 `labs/<课程名>/`。所有课程共享两样东西：

- `common.ini`：板型、编译参数、库版本——保证你电脑上构建出来的固件和别人一模一样；
- `kit/include/pins.h`：全板引脚的唯一事实来源。课程代码里看不到裸数字（`40`、`41`），只有名字（`PIN_TFT_MOSI`、`PIN_TFT_SCLK`）——想知道某根线接在哪，查这一个文件就够。

- **PlatformIO 6.2.0**（锁定在 `pyproject.toml`，由 `uv` 安装），不污染全局环境。
- **pioarduino platform 55.03.312-1**，随附 **Arduino-ESP32 3.3.12**（ESP-IDF 5.5.5）。
- 板型定义 `esp32-s3-devkitc1-n16r8`：16MB 四线 flash + 8MB 八线 PSRAM，与实战派模组完全一致。

### 命令

在仓库根目录执行：

```sh
uv sync                                              # 一次性：装 PlatformIO
uv run pio device list                               # 板子在哪个串口？
uv run pio run -d labs/01-hello -t upload -t monitor # 编译 + 烧录 + 监视，一条龙
uv run pio run -d labs/03-display -t clean           # 某课编译出错时先清缓存
ESP_PORT=/dev/cu.usbmodem212301 uv run pio run -d labs/01-hello -t upload  # 强制指定端口
```

### 烧录的三种姿势（背下来，救命用）

1. **正常烧录**：程序还在跑时点上传，工具会自动按复位进 bootloader。
2. **程序崩了/串口消失**：拔 USB → **按住 BOOT 不放** → 插上 USB → 松开。板子进入 ROM bootloader（串口重新出现），此时永远能烧——bootloader 独立于应用固件，**程序写得再烂也刷不坏它**。
3. **确认板子活着**：`uv run pio device list` 能看到串口，或者 `ls /dev/cu.*`（macOS）里有 `cu.usbmodem*`。

### 接线纪律（虽然这门课不接线）

实战派引脚大量被板载外设占用，**唯一可以自由外接实验的是 GPIO 10、11、21、47**。完整占用表见 `kit/include/pins.h` 头注释。想乱插线之前先看它。

## 第 01 课：认识板子（`labs/01-hello`）

**操作命令**（仓库根目录执行，每课只换 lab 名）：

```sh
uv sync                                              # 首次一次
uv run pio run -d labs/01-hello -t upload -t monitor # 编译+烧录+监视
```

监视器打开后按 **回车** 看身份卡；`Ctrl+C` 退出。端口不对就加 `ESP_PORT=/dev/cu.usbmodemXXXX` 前缀。

**目标**：跑通"写代码 → 编译 → 烧录 → 看日志"的完整闭环；确认硬件是货真价实的 N16R8。

烧录成功后，**在串口监视器里按一下回车**，会打出一张"身份卡"：

```
+---------- ESP32 身份卡 ----------+
| 芯片     ESP32-S3 rev 2, 2 核 @ 240 MHz
| Flash    16 MB   (N16: 应为 16)
| PSRAM    8 MB   (R8: 应为 ~8)
| 空闲堆栈 xxx KB
| MAC      XX:XX:XX:XX:XX:XX
| SDK      v5.5.5
+----------------------------------+
```

为什么是"按回车"而不是开机自动打？S3 的原生 USB 串口在板子复位时要跟电脑重新"握手"（枚举），握手完成前打印的内容会丢。把身份卡做成"回车触发"，你任何时候打开监视器都能拿到——顺手学会了第一个串口输入交互。

同时 RGB LED 缓慢转色轮。**如果 Flash 不是 16 或 PSRAM 是 0，`log_e` 会大声报警**——那是板型配置错了，不是板子坏了。

**代码走读**（`src/main.cpp`）：

- `setup()` 只做三件事：灭灯、开串口、打身份卡。`ESP.getChipModel()` 这一族函数是芯片自描述 API，数据来自 eFuse，不是谁硬编码的。
- `loop()` 里没有一处 `delay()`：色轮每 50ms 走一步（`millis()` 对表），心跳每 5 秒打一行。**`millis()` 返回开机以来的毫秒数**，是非阻塞编程的地基，第 02 课全面展开。
- `rgbLedWrite(pin, r, g, b)` 是 Arduino-ESP32 3.x 内置的 WS2812 驱动，一行点亮 RGB 灯（旧名 `neopixelWrite` 已废弃，编译时每帧刷警告）。

**常见问题**：

| 现象 | 原因 | 处理 |
| ---- | ---- | ---- |
| 找不到串口 | 线是充电线 / 挂在不稳的 hub 上 | 换数据线、直插电脑端口 |
| 上传报 `Failed to connect` | 程序崩溃循环，USB 没重新枚举 | 姿势 2：BOOT + 复位 |
| 日志开头乱码 | 波特率不对 | 确认监视器 115200 |

## 第 02 课：灯光状态机（`labs/02-led`）

**操作命令**：

```sh
uv run pio run -d labs/02-led -t upload -t monitor
```

现象：LED 呼吸，按 BOOT 键切换 彩虹→快闪，串口打 `切换模式 -> xxx`。`Ctrl+C` 退出。

**目标**：写出第一个"产品级结构"的程序——非阻塞 + 状态机。

三种模式循环切换：**呼吸 → 彩虹流动 → 快闪**，按 BOOT 键手动切。

**代码走读**：

- `enum class Mode` + 一个 `switch`：状态机最朴素的样子。**加一种灯效 = 加一个 case 和一个渲染函数**，别的代码一行不动。
- 每种模式是一个 `renderXxx(uint32_t now)`：给它当前时间，它算出现在该亮什么。这就是**用时间推算代替 delay 等待**——主循环永远空转随时可响应，这是嵌入式程序的黄金结构。
- 呼吸灯是三角波近似正弦：`phase/4` 上行、`(2000-phase)/4` 下行，2 秒一个周期。灰度 8bit 直接写进 WS2812 数据，效果等同 PWM。

**实验**：把 `kMaxBrightness` 改成 255 感受一下"刺眼"和"护眼"的差别；把周期 2000 改成 500，观察呼吸变急促。

## 第 03 课：点亮屏幕（`labs/03-display`）

**操作命令**：

```sh
uv run pio run -d labs/03-display -t upload -t monitor
```

现象：屏幕亮起 → 彩条 + "Hello, lichuang!" + 运行秒数；串口每秒打 FPS；BOOT 键调背光 4 档。`Ctrl+C` 退出。

**目标**：点亮 2.0" ST7789，理解 SPI 和 RGB565。

**硬件课**（这块屏的四条关键线，都在 `pins.h`）：

| 线 | 引脚 | 作用 |
| -- | ---- | ---- |
| SCLK | 41 | SPI 时钟：数据位靠它打拍子 |
| MOSI | 40 | 主→从数据线：像素从芯片流向屏 |
| DC | 39 | **命令/数据**切换：低电平=下一个字节是命令，高电平=是像素数据 |
| BL | 42 | 背光，独立 PWM 调光，**低电平点亮**（倒极性！） |

| CS | — | **片选不在 ESP32 手里！** 由 I2C 扩展芯片 PCA9557 的 bit0 控制，低电平选中。用屏前必须先驱动扩展器并拉低它，否则屏全黑——这是本课最大的坑 |

**隐藏关卡：先“敲门”，再说话。** 实战派把 LCD_CS / 功放开关 / 摄像头开关都挂在 I2C 扩展芯片 PCA9557（地址 0x19）上。官方规则：**CS 拉低必须放在屏初始化之前，否则液晶屏无法显示**。所以 `setup()` 里第一批代码是 `initIoExpander()`——配置扩展器（output=0x03, config=0xF8）再把 bit0 拉低。漏了它，你会在真机上得到一块“背光亮着但永远黑屏”的板子，且任何 SPI 参数调不出来（我们真机穷举了 8 种 SPI 组合才找到真凶）。

**代码走读**：

- `rgb565(r,g,b)`：一个像素压进 16bit——红 5 位绿 6 位蓝 5 位。绿色多 1 位是因为人眼对它最敏感。
- `ledcAttach + ledcWrite`：Arduino 3.x 的 PWM API。背光倒极性体现为一行 `ledcWrite(pin, 255 - brightness)`——**硬件行为和代码语义之间的换算只放一处**，其余代码永远说"人话"（越大越亮）。
- `tft.init()` 一口气完成总线 + 面板初始化（引脚和 SPI 参数都写死在 LGFX 类里），`setRotation(1)` 转成 320x240 横屏。
- loop 里整屏重画，每秒打一次 FPS——硬件 SPI + DMA 的吞吐量会让你惊讶。

**排错**：全黑 → 先查 `initIoExpander()` 有没有跑（CS 没拉低是头号原因），再查背光；花屏/颜色怪 → 检查 `pins.h` 与你的板子版本；屏幕180°反了 → `setRotation(3)`。

## 第 04 课：把按键做对（`labs/04-button`）

**操作命令**：

```sh
uv run pio run -d labs/04-button -t upload -t monitor
```

现象：短按换 LED 颜色，长按 ≥800ms 切背光，事件实时上屏 + 串口 `按下 #n`。`Ctrl+C` 退出。

**目标**：从"能用"到"做对"：中断 + 消抖 + 长短按。

短按换 LED 颜色；长按（≥800ms）开关背光；屏幕实时滚动事件流。

**代码走读**：

- **中断**：`attachInterrupt(..., onButtonChange, CHANGE)`——按键的瞬间由硬件捕获，主循环再忙也不漏。ISR 里只有两行：记时间戳、立 flag。**ISR 里禁止 delay/Serial/任何慢操作**，这是铁律。
- **volatile**：ISR 和主循环共享的变量必须声明 `volatile`，否则编译器可能把它缓存在寄存器里，主循环永远看不到变化。
- **消抖**：金属触点闭合瞬间会弹跳几毫秒，一次按压产生一串边沿。靠"距上次有效边沿 <30ms 就丢弃"过滤——简单且够用。
- **长短按**：按下时刻与松开时刻一对比就出来。松开才结算（而不是按够 800ms 立即触发），交互上更自然。

**实验**：把 `kLongPressMs` 改成 3000 试试三档（短/中/长）；把消抖改成 100ms，感受"丢按键"。

## 第 05 课：I2C 总线扫描（`labs/05-i2c-scan`）

**操作命令**：

```sh
uv run pio run -d labs/05-i2c-scan -t upload -t monitor
```

现象：每 5 秒一张"I2C 在线设备"表，应见 0x18/0x19/0x38/0x41 中的若干个（缺 0x38 = 该批次无触摸，正常）。`Ctrl+C` 退出。

**目标**：看懂 I2C，第一次"看见"板载外设。

实战派所有智能外设共用一条两线总线（SDA=1, SCL=2）：

| 地址 | 芯片 | 它管什么 |
| ---- | ---- | -------- |
| 0x18 | ES8311 | 音频 DAC → 扬声器 |
| 0x19 | PCA9557 | IO 扩展器 → 功放开关等 |
| 0x38 | FT5x06 | 屏幕触摸 |
| 0x41 | ES7210 | 音频 ADC → 麦克风 |

**原理**：I2C 每个设备有 7bit 地址。扫描 = 遍历地址发一次寻址，**有人应答（ACK）就代表这个地址住着设备**。`Wire.endTransmission()` 返回 0 就是应答。

**代码走读**：

- `Wire.begin(PIN_I2C_SDA, PIN_I2C_SCL)`：Arduino 默认 I2C 引脚不是 1/2，**必须显式指定**——新手最容易踩的坑。
- `Wire.setClock(400000)`：400kHz 快速模式。板载走线短，稳跑。
- `probe()` 一个函数就是整个 I2C 协议的"敲门"动作——协议复杂，API 却只有两行。

**现象**：每 5 秒一张在线设备表。**这课是进阶篇的地基**：音频篇会直接跟 0x18/0x41 说话，触摸篇跟 0x38 说话。

**排错**：一个设备都扫不到 → 极少见，说明模组 I2C 供电异常；只缺某设备 → 正常（部分批次不含触摸），记下即可。
